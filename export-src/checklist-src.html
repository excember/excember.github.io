The Offload Decision Checklist
1 · The Offload Test — three questions
1Is the knowledge already written down somewhere I can point to?  Thread, ticket, runbook, repo, doc.
2Would two good engineers produce roughly the same answer?  If it depends on who does it, it’s judgment.
3Can I check the result in under two minutes?  This one matters most.
3 yeses
Offload it.
2 yeses
AI drafts, you finish.
0–1 yeses
Keep it. It’s yours.

If you can’t verify it fast, you haven’t saved time — you’ve just moved it.

2 · The four-part handoff — in this order, every time
CONTEXTWho is this for, and what do they already know?
TASKThe one thing you want done — stated as a verb.
CONSTRAINTSWhat to leave out, how long, and what it must never guess at. Include: “If it isn’t in the source, say not determined — don’t guess.”
FORMATThe exact shape you want it back in.

30 seconds to write all four. Saves you three rounds of rework.

3 · The automation trigger

Writing the same prompt a second time? Stop — you’ve found an automation. Save the handoff (a Claude Project’s instructions for language work; a Cursor rules file for file and code work) and point it at new input from then on.
